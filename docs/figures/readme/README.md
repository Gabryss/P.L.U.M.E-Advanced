# README figure sources

These figures document the implementation and inspection work of 7 September
2026. They are checked-in documentation assets; large meshes, reference clouds,
working checkpoints, and generated run directories remain outside this folder.

| Figure | Source and scope |
|---|---|
| `inspection_views.png` | Four CPU-rendered views of the actual full Earth seed-4 GLB, at 0.20 m voxels, without textures or rocks. Cameras are saved with the run. |
| `pipeline.png` | Explanatory diagram of the execution order in `cli.py`; not a simulation result. |
| `host_fields.png` | Stage-A fields reconstructed from the saved seed-4 configuration using the same host generator. |
| `network.png` | Seed-4 `network.json` and `sections.npz`. Equal metric axes in plan view; exaggerated vertical axis in the lower longitudinal plot. |
| `sections.png` | Six original seed-4 Stage-C contours. Four low-junction samples span the ordinary height distribution; two wide locations are selected at least 20 m apart. Before 3D relief and smoothing. |
| `roof_stability.png` | Explanatory section schematic and curves evaluated with `RoofStabilityModel`. Gravity varies; density is 2,900 kg/m³, effective strength 3 MPa, safety factor 1.5. These are conditional roof requirements, not observed body dimensions. |
| `surface_relief.png` | Existing matched-camera before/after comparison on a separate 64 m Earth reach at 0.10 m resolution, with artificial closed ends. Not the seed-4 full tube. |
| `reference_comparison.png` | Replotted medians from the saved Valentine 10 cm cloud / before-relief / after-relief comparison. Only 0.4 m and 0.8 m neighborhoods are shown. No reference point files are reopened by the figure script. |

The two older comparison figures retain their separate experimental context.
No historical celestial-gallery image is presented as a result of the new run.
No image was generated by an AI image model.

The host, network, and section figures omit overall titles and subtitles;
the document captions provide that context. Panel labels and metric axes remain.

## Reproduce

From the repository root, install the core environment, copy
`config/earth_tube_only.toml` to `config/earth_readme.toml`, and change its root
`procedural_seed` to `4`. Then:

```bash
uv run --no-sync python scripts/generate_tube_only.py \
  --config config/earth_readme.toml --output-directory outputs/earth_readme
uv run --no-sync python scripts/render_tube_views.py outputs/earth_readme
```

Pass the same input configuration when building figures:

```bash
uv run --no-sync python scripts/generate_readme_figures.py \
  --run-directory outputs/earth_readme \
  --config config/earth_readme.toml \
  --output-directory docs/figures/readme
```

This reconstructs only the inexpensive host stage. It reads the saved graph,
sections and inspection images; it never generates another network or mesh.
When `--config` is omitted, the builder reads `generation_config.toml` beside
the run artifacts. The saved seed-4 inspection run includes this file with
relative asset paths adjusted for that location.
Reference figures are included when their saved inputs are available under
`outputs/geometry_validation/` and `outputs/surface_relief_study/`; change those
locations with `--validation-directory` and `--relief-study`. If those inputs
are absent, the corresponding existing figure files are left unchanged and
are not listed as regenerated in the new provenance manifest.

For the historical comparisons' methods and regeneration tools, see
[surface relief](../../surface_relief.md) and the
[validation report](../../geometry_validation_2026-09-07.md). Reference data
are obtained separately; the PDC evaluation partition must remain reserved
during development.

[provenance.json](provenance.json) records the input file hashes and figures
produced by the latest documentation build.
